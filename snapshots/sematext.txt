Frequently Asked Questions
What happens at the end of my trial?
At the end of the trial your Monitoring App is automatically disabled, unless you
have set up your payment info. If you have set up payment info, we will automatically start charging
based on the selected plan.
Can I cancel the service?
Of course. You can simply disable any App. You can also fully delete any App at any time and even
close your whole account all by yourself.
Do I need to sign a contract, do I have to commit?
There are no contracts and no commitments. You can cancel any time. Price is metered and based on
the running time for the app / server being monitored. Note: Docker monitoring is based on the base
price and per-container price. The base price includes monitoring of a Docker host and free
monitoring of up to N containers. Per-container price is applied only if you run more than N
containers per host. The number of containers per host is averaged for the whole account. The base
price and the number of containers included in it depends on the plan. We charge at the end of the
month. For longer term and large contracts please get in touch.
Can I use multiple different plans?
Yes. Each Monitoring App is independent
and each App can have a different plan, including the free plan. Each user account can have any
number of Apps.
How many servers or containers can I monitor?
There are no limits to how many servers / instances / nodes / containers you can monitor for Apps
with a paid plan.
Do I have to create my own charts and reports?
You don't have to, though you can. Sematext gives you instant gratification. It knows what type of
application you are monitoring and gives you a number of charts out of the box, neatly grouped into
multiple reports and filterable by tags appropriate for each collected metric. As soon as you
install the agent Sematext will start providing valuable performance insights.
Can I graph my own custom metrics?
Yes. You can send your custom metrics, chart them, alert on them, apply on anomaly detection on
them, create custom dashboards with them, correlate them with other metrics, events, and logs.
How does Sematext compare to New Relic? Datadog? Splunk? Elastic Cloud? AppDynamics?
Sematext is 4-5 times cheaper than New Relic APM. For more information see Sematext vs. New Relic . Datadog
appears more affordable, but forces you to pick a paid plan for your whole account.
Sematext, on the other hand, lets you assign plans to each individual App . This
way you can select the most optimal plan for each App, including the free plan. This is a major
difference whose cost-saving value becomes apparent once you start using Sematext. AppDynamics is
rich, but very expensive and focused primarily on large enterprises and on premises deployments –
see Sematext vs. AppDynamics .

in cost.

What are the locations to run the monitors?
Sematext Synthetics monitors can be scheduled to run from multiple locations around the globe. For
the latest list of locations, refer to the Locations section in our
documentation.
What is a monitor?
A monitor denotes a single HTTP endpoint or website or user-journey you want to monitor. The
monitor is scheduled to run periodically from configured locations and the results are evaluated
based on configured conditions. There are 2 types of monitors: HTTP and Browser monitor. HTTP monitor can be used to
monitor API endpoints, Web URL, or any HTTP endpoint. Browser monitor can be used to
monitor website performance and user journeys.
What is a run?
A run is a single execution of the monitors from a location. For example, a monitor configured to
run every 1 minute from 2 locations will create 2 runs every minute or 86400 runs a month.
How do I know how many monitors or runs I will need?
This depends on your monitoring requirements. Below are a few examples:
&middot; Global availability and performance - 1 HTTP monitor every minute
from 5 locations (216000 runs a month) and 1 browser monitor every 30 mins from 5 locations
(7200 runs a month).
&middot; API performance monitoring - 5 HTTP monitors every 5 mins from 3
locations (129600 runs a month). The number of locations depends on where the majority of
your customers are located.
&middot; Competitive benchmarking - 3 browser monitors every 1 hr from 1
location (2160 runs a month). The number of browser monitors depends on the number of
competitors you want to benchmark with.
&middot; User journey monitoring - 5 browser monitors every 30 mins from 1
location (7200 runs a month). The number of browsers depends on the number of unique user
journeys you want to monitor.
What happens when I use up all monitors or runs?
When you reach the monitor or run limit for a plan, you need to move to a higher plan which allows
more monitors and runs. Else you could also create a new App , with the same plan and add the new
monitors in this App.
What is a user journey?
A user journey is the sequence of actions a user performs while navigating your website. For
example, in the case of an e-commerce website a common user journey is login, search, select
product, add to cart, and checkout. With a browser monitor, you can simulate this user's actions
using a browser script and verify if all the above steps are working correctly and meet your
performance criteria at each step. This is also known as click path or web transactions.
How many APIs or user journeys can I monitor?
The number of APIs or user journeys you can monitor per App is based on the plan. Note that you
can have as many Apps as you wish.
Can I monitor HTTP endpoints/websites that are behind a firewall?
Currently, we do not support a list of static IP addresses that can be whitelisted in your
firewall. If your firewall supports whitelisting based on HTTP headers, we add fixed headers to
HTTP requests sent from HTTP monitor. You can customize the Browser monitor script and add similar
headers.
Will I get charged if the Synthetics App or all the monitors inside the App are disabled?
No. The App needs to record a minimum of 60 HTTP runs or 6 Browser runs in a day to be charged for
that day.
Can I monitor multiple page loads / navigation in a single browser monitor?
You can script a user journey with multiple page loads in a single browser monitor. However, the
page load metrics will be recorded only for the latest page load in the script. For example, if your
script loads the home page and navigates to the login page, only the page load metrics for the login
page will be recorded.
